# 參考報價系統研究

2026 年 10 月讀了 GitHub 上星星最多、而且有報價／估價功能的 7 個開源系統的原始碼，整理它們的做法，挑適合這個專案的部分實作進來。這份文件記錄參考了什麼、為什麼這樣做、哪些刻意沒做。

## 參考的專案

| 專案 | ⭐ | 技術 | 報價功能 |
| --- | --- | --- | --- |
| [midday-ai/midday](https://github.com/midday-ai/midday) | 15k | TypeScript | 沒有獨立的報價單，只有發票；編輯器、取號、品項記憶、客戶快照可參考 |
| [invoiceninja/invoiceninja](https://github.com/invoiceninja/invoiceninja) | 10.3k | PHP / Laravel | 完整：狀態、有效期、核准、轉發票、內含稅計算 |
| [idurar/idurar-erp-crm](https://github.com/idurar/idurar-erp-crm) | 8.9k | Node / React | 報價功能只做了一半；計算方式可參考 |
| [crater-invoice-inc/crater](https://github.com/crater-invoice-inc/crater) | 8.4k | PHP / Vue | 估價單、品項目錄、金額以「分」存整數 |
| [Dolibarr/dolibarr](https://github.com/Dolibarr/dolibarr) | 7.7k | PHP ERP | 商業提案（propal）：驗證時才給號、含稅／未稅兩種價格基準、ODT → LibreOffice 轉 PDF（和我們的 xlsx → PDF 最像） |
| [al1abb/invoify](https://github.com/al1abb/invoify) | 6.4k | Next.js | 和我們一樣是「產生器」，沒有資料庫；表單驗證、PDF 流程可參考 |
| [InvoicePlane/InvoicePlane](https://github.com/InvoicePlane/InvoicePlane) | 3.2k | PHP | 報價狀態（草稿／已送出／已讀／核准／拒絕／取消）、有效期、搜尋 |

## 大家都有的做法

- **單號** = 前綴 + 日期 + 補零流水號（`EST-000001`、`PR2501-0001`、`{$year}-{$counter}`）。做得不好的會在多人同時產生時拿到重複號碼（取最大值 +1 卻沒有鎖），或用伺服器時間而不是單據日期。
- **有效期限**存成日期；「已過期」大多在讀取時判斷，不另外存狀態（Invoice Ninja、midday）。
- **狀態**很少：已報價／成交／未成交／作廢。好的實作在更新時檢查目前狀態（InvoicePlane、Dolibarr 的 SQL 條件），避免兩個人同時改。
- **複製**舊單：保留客戶與品項，重設單號、日期、有效期與狀態。
- **快照**：單據存下當時的客戶與品項資料。直接連到客戶主檔的系統（InvoicePlane、IDURAR），改了客戶資料舊 PDF 就跟著變，是常見的 bug。
- **金額**在伺服器重算，不相信瀏覽器送來的總額（Crater、Invoify 例外，是反面教材）。
- **四捨五入**：每列先四捨五入，再加總；稅額在固定的一個地方四捨五入，遇到 .5 遠離零。
- **含稅價**只有 Invoice Ninja 和 Dolibarr 支援，兩者都讓「未稅 + 稅額 = 含稅總額」剛好相等，差額由未稅金額吸收。

## 採用的做法

| 功能 | 參考來源 | 本專案的做法 |
| --- | --- | --- |
| 報價單號 | 全部 7 個 | `SD` + 年月 + 當月流水號，用報價日期（台灣時間）取號；`BEGIN IMMEDIATE` 鎖住資料庫，多人同時產生不會重號；產生失敗不會用掉號碼；單號不會重複使用（不刪除，改作廢） |
| 報價紀錄與快照 | midday、Crater、Dolibarr | SQLite 存每張單的 JSON 快照，另外保存當初的 Excel 和 PDF；之後選項或客戶資料改了，舊單不會變 |
| 歷史搜尋 | InvoicePlane、Invoice Ninja | 多個關鍵字全部符合，比對單號、客戶、公司、統編、電話、品名；使用者輸入的 `%`、`_` 照字面比對 |
| 複製這張 | Invoice Ninja、InvoicePlane、Dolibarr、midday | 帶入客戶、品項、稅別、備註；出貨日不帶（通常已經過時） |
| 狀態與過期 | Invoice Ninja、InvoicePlane、Dolibarr | 四種狀態；只在狀態沒被別人改過時才更新（否則回 409）；已過期由有效日期即時判斷，不需要排程 |
| 客戶記憶 | midday、Invoice Ninja、Crater | 以統編為鍵，先找上次報價（有聯絡人、電話），再查經濟部 API；只填空白欄位 |
| 品項記憶 | midday、Invoice Ninja | 不維護商品目錄，從報價過的品項自動學習；有統編時優先帶這個客戶上次的價格，避免把 A 客戶的議價帶給 B 客戶 |
| 即時試算 | Invoice Ninja、Crater、midday | 呼叫伺服器同一套計算程式，不在網頁上另外寫一份 |
| 稅額四捨五入到元 | Invoice Ninja、Dolibarr、InvoicePlane | 和統一發票一致；每列金額四捨五入到分；Excel 公式用 `ROUND`，有測試確認 LibreOffice 和 Python 結果相同 |
| 含稅顯示內含稅額 | Invoice Ninja、Dolibarr | `ROUND(總額 × 5/105, 0)`；用 `5/105` 而不是 `/1.05`，因為 1.05 在二進位不精確，遇到剛好 .5 的情況會差 1 元 |
| 常用備註 | Crater、InvoicePlane、Invoify | 備註欄下的快速按鈕 |
| 銷售員聯絡方式 | Invoice Ninja、InvoicePlane | 報價單底部印出負責業務的聯絡方式 |
| PDF 檢查 | Invoify、Dolibarr | 測試確認最長的報價單仍是一頁、中文字型有嵌入 |

## 刻意沒做的

| 項目 | 原因 |
| --- | --- |
| 客戶入口網站、線上核准、電子簽名 | 內部工具；公開連結等於把系統（和發票章）放上網路 |
| 從系統寄信 | 要 SMTP 帳號與寄信信譽；業務已經用自己的信箱和 LINE |
| 報價轉發票、收款、訂金 | 統一發票在會計或電子發票系統開立，另存一份只會不同步；訂金與付款條件用常用備註 |
| 多幣別、多種稅率 | 只用新台幣、單一 5% 營業稅；範本只有一個稅率欄 |
| 商品目錄、客戶主檔管理畫面 | 沒人會維護；從報價紀錄自動學習就夠用 |
| 自訂單號格式、預先顯示單號 | 預先顯示正是其他系統重號的原因；改前綴只要改 `QUOTE_NO_PREFIX` |
| 草稿、版本紀錄 | 產生就定案，要改就複製成新單；快照加上「複製自」就是紀錄 |
| 單列折扣 %、整張折扣欄位、運費欄位 | 範本沒有這些欄位；寫成負數單價的折扣列、或一般品項的運費列就能正確計稅 |
| 用 HTML 產生 PDF、多種版型 | 公司的 `template.xlsx` 已經有發票章與版面；參考的系統大多有中文字型問題 |
